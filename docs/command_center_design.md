# Omni-Agent Command Center — Product Design

## الهدف

تحويل نواة Omni-Agent من واجهة API لا تظهر قيمتها بصرياً إلى لوحة قيادة عملية توضح دورة المهمة كاملة: اختيار نمط التشغيل، تنفيذ المهمة، عرض الوكلاء المشاركين، مراجعة النتيجة، واسترجاع الذاكرة.

## تجربة المستخدم

يدخل المستخدم نص المهمة، ويختار النمط **Auto** أو **Single Agent** أو **Multi-Agent**. في الوضع التلقائي يقرر الخادم النمط بحسب تعقيد المهمة. بعد الإرسال، تعرض اللوحة الحالة الفعلية للخادم والذاكرة المتاحة، ثم تظهر النتيجة من API مع الخطة أو مخرجات الوكلاء، والتقييم النهائي للمراجعة.

| منطقة اللوحة | ما تعرضه | مصدر البيانات الحقيقي |
| --- | --- | --- |
| شريط الحالة | حالة الخادم، نوع الذاكرة، عدد سجلات الذاكرة | `GET /health` |
| مشغل المهمة | النص، النمط، أمثلة مهام | `POST /ask` |
| شبكة الوكلاء | المنسق والوكلاء المشاركون ومراجعة الجودة | استجابة `POST /ask` |
| مساحة النتيجة | الإجابة الموحدة، الخطة، المراجعة، أثر الأدوات | استجابة `POST /ask` |
| ذاكرة الجلسة | أحدث أحداث وحقائق المستخدم | `GET /memory` |
| الثقة والضوابط | الأدوات المسموح بها وسياسة التأكيد البشري | `GET /tools` |

## قرارات التصميم

يعتمد التصميم على واجهة داكنة عالية التباين، وهوية بنفسجية/زرقاء متصلة بالشعار الحالي. كل عنصر في الواجهة مرتبط ببيانات API حقيقية أو يُظهر بوضوح أنه واجهة تصور فقط. لا تعرض اللوحة ادعاءات عن تنفيذ أدوات خارجية لم تُضف إلى النظام.
