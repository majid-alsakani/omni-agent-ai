# ربط الذاكرة الدلالية بقاعدة بيانات خارجية

## الفكرة

يعمل Omni-Agent محلياً دون أي خدمة خارجية باستخدام `LocalVectorBackend`. عند تزويده بمتغير `OMNI_VECTOR_DSN` ينتقل تلقائياً إلى `PostgresVectorBackend`، وينشئ جدولاً باسم `omni_semantic_memory` مع امتداد `pgvector`. تبقى الذاكرة العرضية في ملف JSON حالياً، بينما تُخزّن الحقائق الدلالية في قاعدة البيانات المتجهية.

## الإعداد الإنتاجي

أنشئ قاعدة PostgreSQL خارجية تدعم امتداد pgvector، ثم فعّل الامتداد للمستخدم الذي سيشغّل التطبيق. ثبّت التبعيات الإضافية:

```bash
pip install -r backend/requirements-vector.txt
```

بعد ذلك عرّف رابط الاتصال قبل تشغيل الخادم:

```bash
export OMNI_VECTOR_DSN='postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require'
export ALLOW_LOCAL_VECTOR_FALLBACK=0
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

يُفضّل في الإنتاج حفظ الرابط في Secret Manager وعدم وضع كلمة المرور داخل GitHub أو ملفات المشروع. عند تشغيل التطبيق ينفّذ `ensure_schema()` لإنشاء الامتداد والجدول والفهرس إن لم تكن موجودة.

## شكل البيانات

يحتوي كل سجل دلالي على معرّف، ومعرّف المستخدم، والنص، وبيانات وصفية، وتمثيل متجهي. وجود `user_id` في كل عملية إدخال وبحث يمنع اختلاط ذاكرة المستخدمين. يمكن إضافة `tenant_id` لاحقاً لعزل المؤسسات متعددة العملاء.

## مسار القراءة والكتابة

قبل التفكير، يقرأ الوكيل الذاكرة العرضية الحديثة، ثم يسترجع من pgvector أقرب الحقائق الدلالية للاستعلام. بعد إكمال المهمة، تُحفظ الوقائع المهمة فقط. هذا الفصل يمنع حشر كامل تاريخ المستخدم في كل طلب ويقلل الضجيج والتكلفة.

## الترقية إلى Embeddings إنتاجية

النسخة الحالية تستخدم تمثيلاً محلياً حتمياً بغرض الاختبار. في الإنتاج استبدل `embedding_fn` في `PostgresVectorBackend` بدالة تستدعي مزود Embeddings مناسباً، مع تثبيت أبعاد المتجه في مخطط قاعدة البيانات بما يطابق النموذج. يجب استخدام نفس نموذج التضمين عند الإدخال والاسترجاع، وإعادة الفهرسة عند تغيير النموذج.

## التحقق

يمكن التأكد من نوع الذاكرة النشطة عبر:

```bash
curl http://127.0.0.1:8000/health
```

ستظهر قيمة `vector_store` كـ `postgres-pgvector` عند نجاح الاتصال، أو `local-hashed-vector` في الوضع المحلي، أو `local-hashed-vector-fallback` عند السماح بالرجوع المحلي بعد فشل خارجي.

> لا تُعد قاعدة البيانات المتجهية تدريباً للنموذج. هي طبقة معرفة واسترجاع (RAG/Memory). تدريب النموذج أو Fine-tuning مرحلة منفصلة تحتاج بيانات تقييم وضوابط جودة.
