# Omni-Agent Command Center وData Analysis Lab

## كيف تعمل لوحة التحكم التفاعلية؟

لوحة **Command Center** هي واجهة المنتج التي تُخدَم من المسار الجذري `/` عبر FastAPI. ليست صورة ثابتة: تتصل مباشرة بواجهات النظام، وتعرض حالة المحرك والذاكرة والأدوات، ثم تنفذ المهام أو تحليل البيانات وتعرض المخرجات المنظمة.

| جزء الواجهة | ما يفعله | واجهة الخلفية |
| --- | --- | --- |
| بطاقات الحالة | تعرض حالة الخادم وعدد سجلات الذاكرة ونوع Vector Store والمحركات النشطة | `GET /health` و`GET /tools` |
| مشغل المهمة | يرسل هدفاً نصياً مع وضع `auto` أو `single` أو `multi` | `POST /ask` |
| مخطط التنسيق | يضيء وكلاء البحث والتحليل والمخاطر عند اختيار المسار متعدد الوكلاء ويعرض قرار المراجعة | نتيجة `POST /ask` |
| مساحة النتيجة | تعرض الخطة أو مخرجات الوكلاء والملخص النهائي، ويمكن نسخ الملخص | نتيجة المهمة أو التحليل |
| الذاكرة | تستدعي أحدث الأحداث للمستخدم المحدد، دون عرض محتوى قاعدة بيانات كامل | `GET /memory` |
| Data Analysis Lab | يرفع CSV للتحليل المحلي متعدد الوكلاء | `POST /analyze-data` |

عند الضغط على **تشغيل المهمة**، يقرر وضع `Auto` ما إذا كانت المهمة تحتاج الوكيل الفردي أو منسقاً متعدد الوكلاء. في الوضع متعدد الوكلاء، تُقسّم المهمة على وكيل البحث ووكيل التحليل ووكيل المخاطر، ثم تُراجع المخرجات وتُدمج قبل عرضها. لا يعني ظهور الوكلاء أن النظام نفّذ أثراً خارجياً؛ الأفعال الخارجية تبقى مقيدة بأداة موثوقة وموافقة بشرية.

## تشغيل المشروع محلياً بالتفصيل

ابدأ باستنساخ المستودع وتثبيت التبعيات. يوصى باستخدام بيئة افتراضية لعزل الحزم:

```bash
git clone https://github.com/majid-alsakani/omni-agent-ai.git
cd omni-agent-ai
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
```

شغّل الاختبارات أولاً للتحقق من البيئة، ثم شغّل الخادم:

```bash
pytest -q
uvicorn backend.main:app --reload --port 8000
```

افتح `http://127.0.0.1:8000` لرؤية **Command Center**. افتح `http://127.0.0.1:8000/docs` لرؤية Swagger API. يمكن إرسال طلب إلى API مباشرة أيضاً:

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"حلل فرصة سوق، قارن البدائل، وافحص المخاطر.","mode":"auto"}'
```

## تحليل البيانات التلقائي

يركز **Data Analysis Lab** على ملفات CSV. بعد اختيار الملف، يقوم النظام محلياً بتشغيل ثلاثة اختصاصات مستقلة:

| الوكيل | التحليل الفعلي |
| --- | --- |
| Data Profiling Agent | الصفوف والأعمدة، أنواع الحقول، القيم الناقصة، التكرارات، والإحصاءات الوصفية |
| Insight Agent | أقوى الارتباطات الرقمية، أكبر تباين، والفئات الأكثر ظهوراً |
| Data Quality Agent | درجة جودة من 0 إلى 100 وتحذيرات خاصة بالقيم الناقصة والتكرار والثوابت والقيم الشاذة |

تُعاد النتيجة على شكل ملخص تنفيذي، وبيانات منظمة يمكن للواجهة عرضها. لا يحتفظ الإصدار الحالي بمحتوى الملف المرفوع؛ فقط يسجل ملخصاً مجمعاً عن العملية في الذاكرة العرضية. تقبل الميزة CSV فقط وبحد أقصى 5MB و200 ألف صف و100 عمود.

لتجربة API من سطر الأوامر:

```bash
curl -X POST http://127.0.0.1:8000/analyze-data \
  -F 'file=@tests/fixtures/uci_iris.csv;type=text/csv' \
  -F 'user_id=demo-user' \
  -F 'session_id=data-session'
```

يتضمن المشروع اختباراً حقيقياً على مجموعة **Iris** من UCI. توثق UCI أن المجموعة تتكون من 150 حالة و4 ميزات رقمية وفئة هدف، ولا تحتوي على قيم ناقصة [1].

## سيناريو متقدم جداً: التوأم الاستراتيجي المتعلم

> **الاسم:** Autonomous Decision Twin — توأم قرار استراتيجي يتعلم من الأدلة السابقة ولا يعيد تحليل المشكلة من الصفر.

يُنشأ لكل مؤسسة فضاء ذاكرة متجهي منفصل يحتوي على قرارات سابقة، تقارير أداء، تعريفات مؤشرات، وأسباب قبول أو رفض المبادرات. عندما يصل ملف بيانات جديد، لا يبدأ النظام بتحليل عام فقط. يستدعي المنسق أولاً أقرب حالات سابقة من الذاكرة المتجهية: مثلاً «أطلقنا حملة مشابهة»، أو «كان سبب فشل التوسع السابق هو جودة بيانات المنطقة».

بعد ذلك ينشئ المخطط الذاتي خطة بأدلة محددة: يطلب من Data Profiling Agent التحقق من توافق البنية مع الحالات السابقة، ومن Insight Agent مقارنة الاتجاهات الحالية بمعايير النجاح المخزنة، ومن Data Quality Agent قياس ما إذا كانت البيانات كافية لاتخاذ قرار. ثم يضيف Risk Agent قيود السياسات والامتثال، ويكتب Synthesizer "ملف قرار" يتضمن الدليل، الافتراضات، فجوات الثقة، والخطوة التي تتطلب تأكيداً بشرياً.

| المرحلة | دور الذاكرة المتجهية | دور التخطيط الذاتي | النتيجة المبهرة |
| --- | --- | --- | --- |
| استلام ملف جديد | يسترجع القرارات والتقارير المماثلة حسب المعنى | يحدد ما يحتاج إثباتاً جديداً بدل تكرار العمل | تحليل يبدأ من معرفة المؤسسة لا من صفحة بيضاء |
| التحليل | يوفر معايير تاريخية ومؤشرات نجاح سابقة | يوزع المهام على اختصاصات البيانات والمخاطر | قرارات موثقة بأدلة حالية وتاريخية |
| المراجعة | يقارن الخلاصة بسوابق القبول والرفض | يقرر إن كانت الثقة كافية أو تحتاج دورة تحقق ثانية | مخرج صريح: اعتماد، طلب بيانات إضافية، أو تصعيد بشري |
| التعلم | يخزن فقط القرار المعتمد وسبب القرار ومؤشر النتيجة لاحقاً | يستخدم الذاكرة في المهام اللاحقة | ذاكرة مؤسسية تتحسن مع كل دورة دون حفظ كل التفاصيل الحساسة |

لتحويل هذا السيناريو إلى إنتاج، يجب ربط `OMNI_VECTOR_DSN` بقاعدة PostgreSQL/pgvector، واستبدال embedding المحلي بنموذج Embeddings ثابت الأبعاد، وإضافة أدوار وصلاحيات وAudit Log وواجهة تأكيد بشري قبل أي إجراء خارجي.
